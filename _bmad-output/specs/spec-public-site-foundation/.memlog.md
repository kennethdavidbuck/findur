topic: Focused public site foundation for Findur
updated: 2026-09-19T23:01
---

- (direction) Express distillation: specify the narrow public frontend slice agreed in conversation without adding discovery ceremony.
- (decision) The final Architecture Spine, DESIGN.md, and EXPERIENCE.md remain adopted and authoritative companions; this scope narrows them but does not override them.
- (capability) CAP-1: An unauthenticated visitor can understand Findur from a bilingual landing page; success is accurate communication of portfolio-first discovery, progressive identity reveal, adult-only status, and the evaluation/demo boundary in English and French.
- (capability) CAP-2: An unauthenticated visitor can open a bilingual About page; success is a stable /about route that explains product purpose and current non-public-launch scope in English and French.
- (capability) CAP-3: Visitors can move through the public slice using shared navigation; success is one responsive Public Header and Public Footer used on / and /about with working route, language, theme, and home navigation.
- (capability) CAP-4: Visitors can switch between English and French without losing their route; success is immediate full-page language replacement, persistence in non-sensitive browser storage, and layouts that remain usable with either catalogue.
- (capability) CAP-5: Visitors can select System, Light, or Dark presentation; success is immediate theme application, persistence in non-sensitive browser storage, and live response to OS changes while System is selected.
- (capability) CAP-6: Later public surfaces can reuse the visual foundation; success is landing and About composed from shared tokens and focused layout, typography, action/link, language, theme, header, and footer primitives with consistent interaction states.
- (capability) CAP-7: The public slice is demonstrably robust; success is automated coverage for routes, bilingual switching, theme behavior, navigation, and key accessible semantics plus passing frontend lint, typecheck, test, and build commands.
- (constraint) Implement inside the existing React 19, Vite, and TypeScript frontend and use React Aria Components for interactive primitives as required by AD-16.
- (constraint) The slice is static and backend-independent: no authentication, API integration, protected shell, protected data, or fake successful owner entry.
- (constraint) Follow the Constellation visual direction and DESIGN.md semantic tokens, interaction geometry, responsive rules, and light/dark peer treatment rather than creating a competing style system.
- (constraint) Meet the applicable WCAG 2.2 AA, keyboard, focus-visible, reduced-motion, touch-target, phone/desktop, and 200/400-percent reflow requirements from the adopted UX contract.
- (constraint) Keep English and French catalogues in the frontend; persist only locale and system/light/dark preference in browser storage; tolerate at least 35 percent label expansion.
- (constraint) Preserve the architecture deployment boundary: Vite static output, generic non-sensitive manifest and metadata, SPA route fallback compatibility, and no service worker.
- (decision) Required routes are / and /about only; unfinished Privacy, Terms, Trust and safety, Contact/support, and Guest Demo destinations are omitted rather than exposed as empty links.
- (decision) The public foundation includes focused primitives needed by these pages, not a comprehensive generic design-system package.
- (assumption) Until backend authentication exists, the owner-entry control is visibly unavailable and performs no navigation or network request; its label explains that owner access is coming later.
- (note) Wrapper-only content dropped: effort estimates and conversational debate about whether the slice takes one hour or multiple days do not alter the build contract.
- (assumption) With no stored locale, the public slice starts in English; with no stored theme, it starts in System mode.
- (event) Self-validation Pass 1 — Coherence: PASS. Seven unique capabilities each have intent and testable success; constraints bend implementation; non-goals bound the slice; assumptions are explicit; prose is lean.
- (event) Self-validation Pass 2 — Preservation: PASS. Landing, About, shared header/footer, reusable styles/primitives, EN/FR, System/Light/Dark, backend isolation, React Aria, architecture authority, responsive accessibility, and excluded routes are preserved in the kernel or public-surface contract.
- (event) Spec finalized on feat/public-site-foundation; companion paths resolve, no trailing whitespace or sensitive values were found, and no implementation or commit was included.
